# Decisions

- Jarvis is a standalone app with Good Alarm style features built in. It does not depend on the Good Alarm repo.
- Flutter, Android first. Laptop companion comes in a later phase.
- The Android scaffold is generated by CI (`flutter create`), and `android_overlay/` replaces its manifest and Kotlin files. Reason: the Flutter SDK could not be downloaded in the build sandbox, and the owner builds only through GitHub Actions.
- Alarms use `AlarmManager.setAlarmClock`, which is exempt from the exact-alarm permission and is treated as a user-visible alarm by Android.
- Known limit: every CI run signs with a fresh debug key, so a new APK cannot update over an older install (uninstall first). Fix with a fixed signing key before using Obtainium updates.

## Build-all-phases decisions
- Gemini key is typed into the app (Settings) and stored only on the device, never in backups.
- Undo lives inside the app (Activity page and per-note button), not as notification buttons.
- No Google Drive OAuth sync yet; backup is copy/paste JSON from Settings.
- Handy to Jarvis handoff not built yet; Android Share to Jarvis works today.
- Model name is editable because Google retires models.
- APK is debug-signed. A fixed keystore via GitHub secret is needed before updates install over each other or Play Store.
- Not device-tested. Expect bugs.
